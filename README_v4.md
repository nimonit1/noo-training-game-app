## 概要

10〜40代向けの脳トレゲームのプロトタイプです。短いミニゲーム(12種)を、**目的**(素早さ・記憶・集中・切替・がまん・おまかせ)で選んで遊びます。年代は、はじめの難しさとおすすめ目的の初期値にだけ使います。

- 単一の HTML ファイル(ビルド不要)。ブラウザで開くだけで動きます。
- **外部通信は一切ありません。** CDN・外部フォント・API・解析なし。記録は端末内の `localStorage` にだけ保存されます。
- 結果は遊んだ内容の目安です。診断や治療、認知症の予防を目的としたものではなく、画面でも断定的な効果表示をしません。

設計の経緯・根拠・判断は [DESIGN_v4.md](./DESIGN_v4.md) にまとめています。**最初に DESIGN_v4.md の「5. 結論」と「7.7 次にやること」を読んでください。**

## 動かし方

```bash
# ブラウザで直接開く
open prototype/brain_dojo_v8.html        # macOS の例。ほかの OS はファイルをブラウザへドラッグ

# または、簡易サーバーで開く
python3 -m http.server 8000
# → http://localhost:8000/prototype/brain_dojo_v8.html
```

スマホ幅(390px 基準)で作っています。PC のブラウザでは、開発者ツールでスマホ幅にして確認してください。

## 主な機能

- 年代の選択(10 / 20 / 30 / 40代)。生年月日は聞きません。
- 目的の選択(5種)。目的ごとに「今日のメニュー」3ゲームが決まります。
- ゲーム12種: ルール切替、ストップ&ゴー、ストループ、ひらめきタップ、数字順タップ、ナンバーバック、位置おぼえ、逆順おぼえ、絵おぼえ、周辺ターゲット判断、ダブルタスク、素早く判断。
- 難しさの自動調整(ゲームごとに Lv1〜8)。
- 記録(連続日数、直近7日、ゲーム別ベスト、最近の結果)と、すきま◯分モード。
- 効果音(既定はオフ)。
- 記録の書き出し・読み込み(ファイル。設定画面)。
- ホーム画面に追加して、アプリのように使えます(PWA)。一度開けば、電波がなくても遊べます。

## テスト

Node.js と Playwright(Chromium)が必要です。

```bash
npm install
npx playwright install chromium

npm test            # 12ゲームを完走させ、中断・保存・リセット・横あふれ・連続セッションも確認
npm run test:menu   # 年代ごとのおすすめ目的、目的の切替と保存、すきま◯分などを確認
npm run test:backup # 記録の書き出し・読み込み。不正なファイルや悪意のあるファイルの拒否も確認
npm run test:pwa    # 公開と同じ形で配り、manifest・サービスワーカー・オフライン起動を確認
```

- どれも、ページエラー 0 件・外部リクエスト 0 件を期待します。出力の `problems` / `externalRequests`(`errs` / `ext`)が空であれば正常です。`test:backup` と `test:pwa` は、失敗すると終了コードが 0 以外になります。
- テストは `prototype/` の最新版を自動で選びます(`tests/_latest.js`)。
- テストはゲームの中身を読むために、`window.__dojo`(`peek` / `ui` / `save`)を使います。HTML から消さないでください。
- 実行すると `tests/shots/`(スクリーンショット)と `tests/report_v3.json` が作られます。どちらも `.gitignore` 済みです。

## スマホでアプリとして使う(PWA)

公開ページをスマホで開き、ホーム画面に追加します。

- **iPhone(Safari)**: 共有ボタン →「ホーム画面に追加」
- **Android(Chrome)**: メニュー →「ホーム画面に追加」または「アプリをインストール」

追加すると、アドレスバーのない全画面で開き、一度開けば電波がなくても遊べます。

**記録について(重要)**
- 記録は端末のブラウザの中にだけ保存されます。iPhone の Safari は、しばらく開かないと保存データを消すことがあります。ホーム画面から開くと消えにくくなります(確実ではありません)。
- ホーム画面のアプリの記録は、Safari の記録とは別です。移すときは、Safari で設定画面の「ファイルに書き出す」を押し、ホーム画面のアプリで「ファイルから読み込む」を押します。
- ときどき書き出しておくと、消えたときに戻せます。ファイルには、得点・レベル・日付などだけが入ります。

## 公開のしくみ

`scripts/build_site.sh` が公開用フォルダを組み立てます(`npm run build` で手元でも作れます)。最新版を `index.html` に、過去の版と PWA のファイルを並べ、サービスワーカーにデプロイごとの識別子を入れます。アイコンを作り直すときは `npm run icons` です。

## 開発の進め方

1. 変更するときは、`prototype/brain_dojo_v<次の番号>.html` を新しいファイルとして作ります。既存の版は上書きしません。テスト(`tests/*.js`)が読み込むファイル名も、最新版に合わせて更新します。
2. HTML の冒頭コメントに、テーマ名(一般テーマ)と改訂履歴の表を書きます。
3. 外部通信が必要になる変更は、実装前に、宛先・送るデータ・必須かどうか・ローカルでの代替案を確認します。
4. `npm test` と `npm run test:menu` を実行して確認します。スマホ表示を変えたときは、幅だけでなく、モバイル端末として確認します(Playwright の `devices['iPhone 13']` など。`innerWidth` が端末幅で、表示倍率が 1 であること)。
5. 設計書を改訂するときは `DESIGN_v3.md` のように新しいファイルを作り、変更点と削除したものを明記します。README も同様です。

### デザインルール(抜粋)

- 日本語は游ゴシック、英語は Segoe UI。タイトル 24pt、見出し 18pt、本文 12pt。
- プロトタイプは「一般テーマ」(プライマリ `#0F766E`、セカンダリ `#E0603A`、白背景、本文 `#222222`、補足 `#666666`、赤 `#B71C1C`)。
- 詳細なルールは DESIGN_v4.md の「4.1 ユーザーの設計ルール」にあります。

## デプロイ(GitHub Pages)

`main` ブランチに PR をマージすると、GitHub Actions(`.github/workflows/deploy.yml`)が自動で次を行います。

1. Playwright のテスト(`npm test` / `npm run test:menu`)を実行
2. 成功したら、`prototype/` の最新版(番号が最大の `brain_dojo_v*.html`)を `index.html` として GitHub Pages に公開

- 初回のみ、GitHub のリポジトリ設定 **Settings → Pages → Source を「GitHub Actions」** に変更してください。
- 公開 URL: `https://nimonit1.github.io/noo-training-game-app/`
- 外部サービスへの通信やシークレットは使いません。手動実行は Actions タブの「Run workflow」から行えます。
